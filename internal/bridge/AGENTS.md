# internal/bridge — CAT bridge subsystem (design detail)

This scoped, tool-neutral guidance applies when working under `internal/bridge/`.
It holds the bridge subsystem's design, decision, and gotcha detail without
expanding the root instruction kernel. Retired session history is routed by
`docs/session-handoff.md` and its retirement record.

- **`internal/bridge` subsystem** per ADR 0013 + ADR 0019 — daemon subsystem providing `/v1/rig/events` SSE for the logging SPA. **M3a closed 2026-05-11.** v1 is **read-only for state display**: rig pushes state via AUTO-mode CAT, bridge filters and forwards via SSE, SPA displays. A narrow **inbound command path** landed 2026-06-04 per **ADR 0026** — `POST /v1/rig/command` (single or atomic `{commands:[…]}` batch) + `bridge.SendCommands` + data-driven `cat` commands (`value_map`/`pad`/`exposed`); `BridgeInfo.ops` advertises the exposed ops; confirm-by-push validated on the FTdx10. SPA rig-control shipped — VFO swap + band step/jump + **freq step** (Shift+Ctrl+↑/↓ = ±100 Hz coarse, Shift+Ctrl+→/← = ±10 Hz fine, Shift+Ctrl+Alt+↑/↓ = ±5 kHz band hop — all on the arrow cluster; Page keys avoided because Firefox's Ctrl+Shift+PageUp/Down move-tab won't yield to preventDefault) on **Shift+Ctrl** shortcuts (`actions/rigControl`). Freq step tunes the **selected** VFO: CAT-off edits `manualState`; CAT-live drives `set_freq` (`FA`, VFO-A) or `set_freq_b` (`FB`, VFO-B) — per-physical-VFO ops, SPA routes by selection — with an optimistic per-VFO target so key-repeat survives confirm-by-push lag. **VFO swap** drives `swap_vfo` (`SV;` — swaps A↔B; `VS`/select doesn't move the operating freq). **Mode** dropdown drives `set_mode` when live (**Option A**: the dropdown shows the rig's OWN mode literals from `rigModes` — e.g. LSB/USB/CW-U/DATA-U — and a pick sends the literal; CAT-off shows operator-friendly modes → `manualState`; the log always records ADIF via `displayedState`, which resolves the literal). A **tune-carrier path** landed 2026-06-04 per **ADR 0027** — `POST /v1/rig/tune {active}` drives a daemon-owned TX state machine that keys a reduced-power **RTTY** carrier for tuning an external linear amp (the first feature that transmits): the daemon owns the guaranteed stop (hard auto-off + release-on-disconnect + single-flight), snapshots+restores mode/power, and clamps tune power (const 20 W, config ≤ 40 W) + auto-off (const 15 s, config ≤ 30 s) at hard code ceilings; `tx_on`/`tx_off` are **never `exposed`**, so only the controller can key TX. Tune-OFF is **two writes** (task #270): `TX0;` alone (the guaranteed-stop unkey), then — after a TX→RX settle (`bridge.tune.restore_settle_ms`, default 150 ms, clamp ≤ 2 s) — the best-effort `PC…;MD0…;` restore, because the FTdx10 drops a mode change sent in the same burst right after `TX0;`. `BridgeInfo.tune` advertises it; the SPA shows a **click-only** Tune button driven by the `tune-state {active}` SSE event. Durable mechanisms future work must know:
  - **Rig-mode → ADIF translation:** bridge is a pure pass-through (rig literal on the wire); the SPA resolves to ADIF (MODE, SUBMODE) pairs via per-rig mappings in two layers — rigdef defaults in `internal/cat/rigs/*.json` under `mode_mappings` + operator overrides in `config.json` under `bridge.mode_mappings`, merged at `/v1/config` GET time. Edited via the config SPA's Rigs tab (`ModeMappingsEditor`) — the logging SPA's My Station Mode Mappings sub-tab was removed 2026-06-25 (config SPA owns rig/mode setup).
  - **Error codes + i18n (ADR 0010 rev 6):** `bridge-error` / `rig-disconnected` payloads carry `{code, details}`, not human strings; the SPA's `lib/i18n/` catalogue (`en.ts` baseline; planned `ny.ts`/`tum.ts`) renders code + details. Retune wording by editing `en.ts` — no daemon restart.
  - **Data-driven modes:** `internal/enums/modes` loads embedded `adif-modes.json` baseline + optional `$SM_WORKING_DIR/modes.json` override at startup; ADIF growth needs no binary release.
  - **Pipeline supervisor (ADR 0020):** `runSupervisor` wraps `runPipeline`, classifies exits (permanent/transient/context-cancelled), retries transient faults with exponential backoff (1s→30s cap; tunable via `bridge.timeouts.{backoff_initial_ms,backoff_max_ms}`) so first-boot ordering and mid-session disruption self-heal without restart. INIT+READ re-fire each cycle. **Liveness default 5s** (`bridge.timeouts.liveness_ms`) since the FTdx10 family doesn't surface kernel disconnects on rig-off. **Serial write watchdog default 500ms** (`bridge.timeouts.write_watchdog_ms` → `serial.Config.WriteTimeoutMS`; was 2s until the ADR 0064 amendment, 2026-08-07): `go.bug.st/serial` has no write deadline, so a hung `port.Write` (driver/HW fault) is bounded by closing the port (→ `ErrWriteTimeout` → teardown → supervisor reopen), which stops a hung tune-off write from wedging the guaranteed-stop. The watchdog is ALSO the true fault-path bound on how long an emergency unkey can queue behind ADR 0064's keyed-interval meter-poll write — a ctx deadline cannot interrupt a blocked `write(2)` — which is why the default tightened when that poll landed. The rigdef's own `write_timeout_ms` stays unused (too tight for a port-closing backstop). SPA flash-suppression (`FLASH_SUPPRESS_MS=800ms` in `bridge.svelte.ts`) means brief rig blips produce zero toast noise while genuine outages surface within ~1.5s.
  - **Tune-restore snapshot (ADR 0027):** the bridge keeps a minimal mode+power snapshot (fed by the read loop, **frozen while a tune is active** so the rig's own RTTY/tune-power pushes can't pollute it) so the daemon-owned tune controller restores the pre-tune state — the one scoped exception to "no persistent rig-state cache." Cleared on disconnect; the controller **refuses to start a tune if mode+power are unknown** (can't guarantee the restore). TX keying goes through this controller only, never the generic command path.
  - Default deployment is single-binary (daemon imports the bridge package); split-host `cmd/bridge` is opt-in and parked.
  - **Not in v1:** phone/CW PTT-for-operating (QSO keying), inbound rig control beyond the landed ops + tune (ADR 0026 + ADR 0027 cover those; see above), rigctld-compat TCP, NDJSON Unix-socket frontend, persistent rig-state cache beyond two scoped exceptions — hub caches (one slot each for `bridge-error`/`rig-disconnected`/`tune-state` replay to late subscribers; disconnect cache clears on next `rig-state` per ADR 0009) and the tune controller's mode+power restore snapshot (ADR 0027).
  - Retired session-by-session history: `docs/session-handoff.md`; use its Git retrieval route only when needed.
