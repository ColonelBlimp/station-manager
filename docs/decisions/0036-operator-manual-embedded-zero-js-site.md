# 0036 — Operator manual as a self-contained zero-JS Hugo site, embedded and on-disk

## Context

There is no consolidated operator manual. The operator-facing facts are scattered
through docs that are really contributor docs with operator sections bolted on:
`install.md` (install + CAT setup), `ft8.md` (explicitly "operator **&** contributor"),
and `keyboard-shortcuts.md` (a flat inventory, not a task walkthrough). A standing
memory note flagged a consolidated, end-to-end operator manual as future work — "don't
start unprompted." It is now prompted.

The forcing function is the **first external deployment** (7Q8AC, Fedora). That reader
is the archetype: a licensed ham who knows radio but nothing of SM's internals, who did
*not* build or install SM themselves, operating over a slow/unreliable link. They have
*the manual* and nothing else — not the repo, not the other docs, possibly no internet at
read-time, possibly reading from disk because the daemon won't start. The manual must be
**task-oriented**, **operator-only**, and **self-contained**.

## Decision

Ship an operator manual as a **self-contained, zero-JS static site** generated by **Hugo**
from per-chapter markdown, assembled into a **single HTML page**. The built site is
`go:embed`-ed into the daemon and served at **`/manual`** (behind the existing
`ServeSPA && Protocol==tcp` gate), and the *same* static output is shipped in the RPM
(`/usr/share/doc/station-manager/`) so it opens from `file://` when the daemon is down.
The Hugo project lives in a top-level `manual/` directory.

## Alternatives considered

### Summarize-and-link (manual links out to canonical reference docs)
The doc-map's "small set of sources of truth" rule favours this — the manual carries the
operator narrative and links to `config.md` / `keyboard-shortcuts.md` for exhaustive
detail. Rejected: the operator does **not** have the rest of the repo. A "see the canonical
reference" link is useless to a remote, possibly-offline reader. Self-containment is the
overriding requirement; the resulting table duplication is accepted as a release-discipline
cost, not a single-source-of-truth violation.

### Lift all operator content out of the contributor docs
Move every operator paragraph out of `install.md` / `ft8.md` into the manual and trim those
to internals only. Rejected as the *blanket* policy: a full lift churns the contributor docs
and risks a window where both are half-right. We will lift only chunks that are *purely*
operator-facing and misfiled (opportunistically), leaving the contributor/reference docs in
place.

### Hosted docs site (GitHub Pages, Algolia/DocSearch)
Polished, free for open source. Rejected: needs the internet at read-time, which kills the
offline + flaky-link + self-contained requirements outright.

### Go-native generator (goldmark + a hand-rolled template)
No new toolchain; stays pure-Go. Viable, but we would hand-build the layout/templating
chrome. Hugo is itself a single Go binary, used at **build time only** (never linked into
the daemon), and gives the layout/templating machinery for a small cost — judged worth the
one build-time dependency.

### Pagefind (build-time indexer, client-side search box)
The modern "proper docs" search. Rejected: it loads its index in chunks via `fetch()`, which
browsers block under `file://` (every local file is an opaque origin → CORS error). It would
fail precisely in the daemon-down-on-disk scenario we most need search for.

### Fuse.js / Lunr.js with a `<script>`-embedded index (zero-CORS search box)
A real search box that works from both `/manual` and `file://`, provided the index is loaded
as a `<script>` (not `fetch`ed). Viable, but adds JS plus an index that must be kept in sync
with the content. For an ~11-chapter **single page**, the browser's own Ctrl-F sweeps the
whole manual at once — sufficient. Rejected in favour of staying zero-JS.

### Multi-page site
Hugo's default (one output page per content file). Rejected: Ctrl-F only searches the current
page, so multi-page would mean per-chapter searching. A single page lets one Ctrl-F cover
everything, makes `file://` bulletproof (no inter-page links), and prints as one document.

### In-app `/manual` only (no on-disk copy)
Simplest delivery. Rejected: a daemon-served site is unreachable *before* first run and when
*the daemon won't start* — the exact troubleshooting moment docs are needed. The on-disk copy
closes that gap for free (same static output).

### Standalone PDF as the primary/only artifact
Printable, portable. Not needed as a separate pipeline: the on-disk static HTML covers the
offline and daemon-down cases, and Hugo's HTML prints acceptably. A dedicated PDF output can
be added later from the same source if demand appears.

## Consequences

- **New build-time dependency:** the Hugo binary in CI and the release flow. It joins the
  host-side pre-build step (alongside the SPA, which is already pre-built on the host and
  embedded), so it stays **out of the AlmaLinux release container** and is **never linked
  into the binary**.
- **Custom minimal zero-JS layout** is required (not an off-the-shelf theme): assembling one
  page from per-chapter content needs a custom layout anyway, and most Hugo docs themes ship
  JS (collapsible sidebars, search). Owning the layout is what guarantees the "no JS" promise.
  Navigation is a sticky **CSS-only TOC sidebar** of anchor links; it collapses/stacks on
  narrow screens via CSS.
- **Authoring stays per-chapter markdown** (`manual/content/…`, weighted) → reviewable diffs;
  the single page is an output concern, not an authoring one.
- **Self-containment duplicates reference tables** (shortcuts, file locations, CLI flags) that
  also live in canonical docs. Drift is mitigated by a **release-checklist line** ("re-sync
  the manual's tables") and is bounded to between-releases. The embedded `/manual` copy is
  **version-matched for free** (compiled into the same binary); only the operator's on-disk
  copy can lag, and only until the next RPM.
- **New route `/manual`** behind the `ServeSPA && tcp` gate; a new `go:embed`. Daemon binary
  grows by the embedded site (small — prose + CSS).
- **`#`-anchors enable later contextual deep-linking** (e.g. a Help affordance pointing at
  `/manual#ft8`), working identically over HTTP and from disk.
- **FT8 attended-only** is stated plainly in operator language in the manual — this is the
  right home for that constraint facing the operator (see ADR 0031 and the attended-only memory).
- **Top-level `manual/`** keeps a full Hugo project tree out of `docs/`'s tier conventions;
  `docs/README.md` will register `manual/` as the operator-manual source and note the built
  site is a shipped artifact (done at scaffold time).

## Triggers to revisit

- **The manual outgrows a single page** (load/scroll/print becomes unwieldy, or Ctrl-F across
  it is impractical) → reconsider multi-page + a `<script>`-embedded Fuse/Lunr index.
- **A non-RPM target appears** (DEB, tarball, musl/Alpine) → revisit how the on-disk copy is
  packaged (the `/usr/share/doc` path is RPM-shaped).
- **Operator demand for a true PDF** beyond browser-print → add a PDF output from the same
  Hugo source.
- **The manual needs translation** (Tumbuka/Chichewa, matching the SPA i18n direction) →
  Hugo multilingual changes the single-page assembly and the sidebar.
- **A second/many operators with materially different rigs or workflows** → the "one manual"
  assumption may need per-deployment variants or a config-aware section.
