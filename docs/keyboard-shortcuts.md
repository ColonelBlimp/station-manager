# Station Manager — keyboard shortcuts

**Purpose:** running inventory of every keyboard shortcut wired up in the
logging SPA, kept in sync with the code so the user-facing manual can
draw from one source. Each row pins:

- **Where** it fires (window-level, or a specific component / focus
  context).
- **The keys** themselves, including modifier behaviour on macOS where
  it differs.
- **What it does**, in operator language.
- **Source** — the file + the handler function so the next contributor
  can find the gate logic without grep gymnastics.

When a new shortcut is added, append it here and reference this doc in
the user manual update. When one is removed or rebound, update the row
in the same commit as the code change. Treat this doc the same as
`docs/session-handoff.md` — stale rows are worse than no rows.

---

## Global (window-level)

These fire regardless of where focus is, with the documented exceptions.

| Keys                          | Action                            | Notes                                                                                                                                                                                                                                                                                          | Source                                                                                  |
| ----------------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **ESC**                       | Clear the QSO form                | Same effect as the Clear button. No-op while the QSO Edit Overlay is open — the overlay's own ESC owns that case so dismissing the overlay doesn't also wipe the live draft underneath. After clearing, focus returns to the Callsign field.                                                  | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown`                  |
| **Ctrl + Enter** / **⌘+Enter** | Log the QSO                       | Same effect as the Log QSO button. Gated on `qsoDraft.canSubmit` — the shortcut does not bypass validation. macOS gets ⌘+Enter via `metaKey` for native feel. After a successful log, focus returns to the Callsign field. No-op while the QSO Edit Overlay is open.                            | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown`                  |
| **F2**                        | Lookup-only (enrichment + contact history) | Fires the same enrichment + contact-history fetch as Tab, but does NOT start the QSO timer (`qsoDraft.qsoStarted` stays false; `qsoDate` / `timeOn` keep paired-ticking). The pile-up workflow: type a callsign, hit F2 to scan station info / DXCC / past contacts, decide whether to commit — Tab is the commit signal, F2 is the peek. Gated on a valid callsign in the form (same `isValidCallsign` check as Tab); empty or invalid input is a silent no-op. Fires regardless of focus context — F2 is a function key with no typing collision risk, which is the whole point (operator's hands stay on the keyboard while the cursor is in the Callsign input). No-op while the QSO Edit Overlay is open. | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown` / `handleLookupShortcut` |
| **F3**                        | Mirror whichever TimerControls button is currently enabled | Stop the timer if it's running. Start it if it's stopped AND a lookup (F2 or Tab) has run for the current callsign (the same gate as the Start button's disabled state). Silent no-op when neither button is enabled — e.g. callsign field empty, or operator has edited the callsign after lookup. After Stop: time fields resnap to "now" and paired-ticking resumes; typed callsign / name / RST stay — F3 is "abandon timer," not "clear form." After Start: time fields snap to "now" and pin (timeOff keeps ticking). preventDefault'd to defang the browser's default Find-Next. No-op while the QSO Edit Overlay is open. | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown` (gates: `startEnabled` / `stopEnabled` derived); methods on `frontend/logging/src/lib/states/qsoDraft.svelte.ts` — `startQso` / `stopQso` |
| **Shift + Enter**             | Stack the current callsign       | Push the trimmed/uppercased `qsoDraft.callsign` onto the pile-up stack (`callsignStack.items`), then reset the per-callsign draft (callsign / name / qth / RST / comment / notes / enrichment / contact history) via the same flow as ESC — only the side effect of pushing differs. Empty or invalid callsign is a silent no-op (matches F2 / Tab's gate). Duplicate push (call already on the stack) is silently rejected. Focus returns to the Callsign field for the next caller. No-op while the QSO Edit Overlay is open. | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown` / `handleStack`; state on `frontend/logging/src/lib/states/callsignStack.svelte.ts` |
| **Shift + ↑**                 | Pop the newest stacked callsign  | Load the top (most-recently-stacked) call into `qsoDraft.callsign` and remove it from the stack. Destructive overwrite: any half-typed call in the field is lost (use Shift+Enter to stash it first). Silent no-op when the stack is empty. preventDefault'd so the browser's native shift-arrow line-select doesn't fire alongside. **Guarded `!ctrlKey && !metaKey`** so it does NOT fire for Shift+Ctrl+↑ (that's the ±100 Hz coarse freq-step below). No-op while the QSO Edit Overlay is open. | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown` / `handlePopTop`; state on `frontend/logging/src/lib/states/callsignStack.svelte.ts` |

Same destructive-overwrite + empty-stack-no-op semantics as Shift+↑, and the same `!ctrlKey && !metaKey` guard (Shift+Ctrl+↓ is the ±100 Hz coarse freq-step). preventDefault'd for the same reason. Focus moves to the Callsign field. No-op while the QSO Edit Overlay is open. | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown` / `handlePopBottom`; state on `frontend/logging/src/lib/states/callsignStack.svelte.ts` |
| **Shift + Ctrl + \\**          | Swap the selected VFO (A↔B)       | Same effect as clicking the unselected VFO box. CAT off → local `manualState` swap; CAT live + rig exposes `set_vfo` → sends `set_vfo` (the new VFO arrives over `/v1/rig/events`, confirm-by-push); CAT live + no `set_vfo` capability → silent no-op. Fires regardless of focus, `preventDefault`'d. No-op while the QSO Edit Overlay is open. | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown`; action in `frontend/logging/src/lib/actions/rigControl.ts` — `swapVfo` (→ `selectVfo`) |
| **Shift + Ctrl + ]** / **Shift + Ctrl + [** | Band up / band down     | Steps the rig one band up/down via native `BU0;`/`BD0;` (main band; the `0` param selects main vs sub) — the rig restores that band's stack memory (last freq + mode), and the new band shows via the resulting `FA` push (confirm-by-push). CAT-live + capable only (no manual equivalent — no rig to step); silent no-op otherwise. `preventDefault`'d, no-op while the QSO Edit Overlay is open. | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown`; actions `frontend/logging/src/lib/actions/rigControl.ts` — `bandUp`/`bandDown` |
| **Shift + Ctrl + 1…0**        | Jump to band (direct)             | Sends `set_band` → `BS<code>;` for the keyed band — 1=160m, 2=80m, 3=40m, 4=30m, 5=20m, 6=17m, 7=15m, 8=12m, 9=10m, 0=6m (60m omitted — use band-step). Matched on the physical digit (`e.code`) since Shift+digit is a symbol. CAT-live + capable only; new band shows via the `FA` push. `preventDefault`'d, no-op while the QSO Edit Overlay is open. | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown` (`bandByDigit`); action `frontend/logging/src/lib/actions/rigControl.ts` — `selectBand` |
| **Shift + Ctrl + ↑** / **Shift + Ctrl + ↓** | Tune the selected VFO ±100 Hz (coarse) | Nudges the **selected** VFO's frequency up/down 100 Hz (↑ = higher). CAT off → edits the selected VFO's `manualState` freq directly (both VFOs are local). CAT live → drives the rig: `set_freq` (`FA`) for VFO-A, `set_freq_b` (`FB`) for VFO-B, each capability-gated on its own op — a live nudge no-ops if the rig doesn't expose the relevant command (e.g. VFO-B selected on a rig with only `set_freq`). New freq shows via the `FA`/`FB` push (confirm-by-push). Uses an optimistic per-VFO target so fast key-repeat tracks cleanly despite push lag (re-syncs to the displayed freq after a ~350 ms pause). Distinguished from the plain Shift+↑/↓ stack-pop by the Ctrl modifier (the stack handlers are guarded `!ctrlKey && !metaKey`). `preventDefault`'d. No-op while the QSO Edit Overlay is open. | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown`; action `frontend/logging/src/lib/actions/rigControl.ts` — `nudgeFreqCoarse` (→ `nudgeFreq`) |
| **Shift + Ctrl + →** / **Shift + Ctrl + ←** | Tune the selected VFO ±10 Hz (fine) | Same behaviour and routing as the ±100 Hz coarse step above, but 10 Hz per press — the fine-tuning nudge (→ = +10 Hz, ← = −10 Hz). All four freq-step keys sit on the arrow cluster (↑/↓ coarse, →/← fine). **Page keys were avoided deliberately** — Firefox's Ctrl+Shift+PageUp/Down move-tab won't yield to `preventDefault`. `preventDefault`'d. No-op while the QSO Edit Overlay is open. | `frontend/logging/src/lib/ui/panels/QsoPanel.svelte` — `handleKeydown`; action `frontend/logging/src/lib/actions/rigControl.ts` — `nudgeFreqFine` (→ `nudgeFreq`) |
| **ESC** (in modal overlay)    | Dismiss the QSO Edit Overlay      | Active only when the overlay is open. Suppressed while a save is in flight (the operator's intent during save is to wait, not cancel). Cancel button + click-outside-the-card are the equivalent mouse paths.                                                                                  | `frontend/logging/src/lib/ui/components/QsoEditOverlay.svelte` — `handleKeydown`        |

> **Tune carrier (ADR 0027) is deliberately click-only.** The Tune button (`frontend/logging/src/lib/ui/components/TuneButton.svelte`) has **no** keyboard shortcut, unlike the rest of the rig-control family above. Keying a transmission should be a deliberate, visible action — not a stray keypress — so the omission is a safety choice, not a gap. Don't "complete the set" with a Shift+Ctrl+T.

| VFO frequency input (focus inside) | **ESC**         | Cancel the edit                                     | Reverts the displayed value to the parent's `value` and blurs the input. | Comment paste-list popover (open)  | **ESC**         | Close the paste-list dropdown                       | Active only when the Comment field's recent-comments popover is open (the clipboard-list icon trigger on the label row). ## Component activation (button-role keyboard parity)

These mirror what a mouse click on the same element would do — they exist
so a keyboard-only operator never gets stuck.

| Element                                    | Keys                  | Action                                              | Notes                                                                                                                                                                                                                                                                                                                          | Source                                                                                  |
| ------------------------------------------ | --------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| VFO box (rig label "VFO-A" / "VFO-B")     | **Enter** / **Space** | Select that VFO (swap)                              | Equivalent to clicking the box. The box itself is intentionally NOT in the keyboard tab order (`tabindex={-1}`) per ADR 0009 — operators reach the swap action via a mouse click, the **Ctrl+\\** global shortcut (now wired — see the Global table), or Enter/Space when focused. Actionable when CAT is off (local `manualState` swap) or when CAT is live and the rig exposes `set_vfo` (drives the rig, confirm-by-push); a no-op for the already-selected box, and disabled when CAT is live but the rig lacks `set_vfo`.                                              | `frontend/logging/src/lib/ui/components/VfoBox.svelte` — `handleKeydown`                |
| SessionPanel row                           | **Enter** / **Space** | Open the QSO Edit Overlay for that QSO              | Equivalent to clicking the row. Fires the same `GET /v1/qso/{uuid}` → populate flow. While a fetch is in flight or another overlay is already open, the click is ignored to prevent double-trigger.                                                                                                                            | `frontend/logging/src/lib/ui/panels/SessionPanel.svelte` — inline `onkeydown` on the `<tr>` |
| QSO Edit Overlay backdrop                  | **Enter** / **Space** | Dismiss the overlay                                 | Only fires when the focus target is the backdrop itself, not a descendant. Equivalent to clicking outside the modal card. Suppressed while a save is in flight.                                                                                                                                                                | `frontend/logging/src/lib/ui/components/QsoEditOverlay.svelte` — inline `onkeydown` on the backdrop `<div>` |
| TimerControls start / stop buttons         | **Enter** / **Space** | Start or stop the QSO timer                         | Native `<button>` keyboard activation. Disabled state derived in QsoPanel: **Start** disabled until a callsign is typed AND F2 / Tab has run a lookup for it (matches `qsoDraft.lookupCallsign`); Stop disabled when `qsoStarted=false`. Editing the callsign post-lookup re-disables Start until the next lookup. F3 is the focus-independent equivalent that respects the same gates.                                                                                                                                     | `frontend/logging/src/lib/ui/components/TimerControls.svelte` — `<button onclick={onStart}>` / `onStop`     |
| Callsign field stack icon (`≡`)            | **Click**             | Stack the current callsign (mouse equivalent of Shift+Enter) | Mouse-only affordance — `tabindex={-1}` keeps it out of the operator's tab order so the keyboard flow goes Callsign → RST → … without an icon stop. Fires the same `handleStack` as Shift+Enter (push + clear). Title attribute exposes the shortcut for discoverability. Only renders when an `onstack` callback is passed to the Callsign component, so other Callsign instances (e.g. setup form) don't carry the affordance. | `frontend/logging/src/lib/ui/components/Callsign.svelte` — `<button onclick={onstack}>` |
| StackingDrawer entry                       | **Click**             | Pop that callsign into the form                     | Loads the clicked call into `qsoDraft.callsign` and removes it from the stack (pop = load; single action / single effect). Mouse equivalent of Shift+↑ / Shift+↓ for picking by visual position rather than stack order. Focus moves to the Callsign field afterwards. | `frontend/logging/src/lib/ui/cards/StackingDrawer.svelte` — `pop(index)` |
| StackingDrawer header `×`                  | **Click**             | Discard the entire stack                            | Drops every entry. No undo — symmetric with the rest of the stack design ("no undo for now"). Drawer auto-hides on the next render since visibility is `callsignStack.items.length > 0`. | `frontend/logging/src/lib/ui/cards/StackingDrawer.svelte` — `discardAll` |

## Browser / native (called out for completeness)

These are not project-wired but worth documenting for the user manual:

- **Tab / Shift+Tab** — normal field navigation. The form's tab order is
  Callsign → RST Sent → RST Rcvd → Mode → VFO (selected one only;
  non-selected VFO is skipped unless split mode is on) → Name → QTH →
  Comment → Date → Time On → Time Off → Clear → Log QSO.
- **ESC** in a `<select>` (e.g. Mode dropdown) — closes the dropdown
  natively. The window-level ESC handler still fires the Clear action
  on the same keypress; this is intentional and the existing behaviour
  hasn't been a friction point.
- **ESC** in a date / time picker — varies by browser; native pickers
  typically close on ESC, then the window-level Clear fires on a second
  ESC. Not project-controlled.
